🧠 Part 1: The ARM architecture

Unit 3.1. One question for the whole part: why is ARM in your phone and the Raspberry Pi, but x86 in many desktops?

What is ARM?

ARM is a family of processors built on the RISC idea. Arm Holdings designs them and licenses the design to other companies, who make the chips.

RISC: simple instructions, quick to run, little power and heat.
CISC (Intel/AMD x86): complex instructions that take many cycles, more power and heat.

Benefits of ARM: small size, low energy, little heat, tightly coupled memory (fast, good for real-time tasks), and cheaper chips.

Sort: ARM or x86?

How ARM chips are made, and the three profiles

  1. Select the architecture for the implementation.
  2. Design the CPU: schematics, transistors, logic gates, clocking.
  3. Build it: fabricate transistors on a silicon wafer, extract the dies, assemble the CPU.

Software must be adapted: x86 programs do not run natively on ARM. Developers recompile or cross-compile them, and watch endianness and libraries.

Which profile fits?

How to teach this: Contrasting cases

TechniquePut two things side by side. Ask: what’s the same, what’s different, when is each better?
Why it worksComparing builds understanding of criteria like power, heat and speed, not just facts.
In classHalf the class lists ARM facts, half lists x86 facts. Merge them into Table 3.1.
Watch outDon’t say one is “better”. Each fits a different job.

🌐 Part 2: Remote access with SSH and VNC

Unit 3.2. Same Raspberry Pi, two ways to reach it.

What and why

Remote access is the ability to access a computing device from another device in a remote location, over a network.

  • IT support connects to an employee’s computer.
  • Staff work off-site on the office network.
  • Students use powerful lab computers from home.
  • Files are shared between devices.

On a Raspberry Pi: edit a robot’s program, control smart-home IoT devices, update electronic road signs in real time.

Risk: others can also get in. Secure it when you set it up.

Which one would you use?

How to teach this: Scenario decision cards

TechniqueGive short real-life cases. Learners pick the best option and give a reason.
Why it worksIt moves learners from definitions to choosing, which is how exams and jobs test it.
In classGroups write 3 scenarios, swap with another group, then answer.
Watch outAvoid scenarios where both answers work. Include one that needs a trade-off.

⌨️ Part 3: Edit a file with Nano

Unit 3.3. Type real commands in the practice terminal. No Pi needed.

Why Nano, and the commands

Over SSH you only have a terminal, so you edit files with a terminal editor like Nano.

TaskCommand or key
Install Nanosudo apt install nano
Create a filetouch notes.txt
Backup firstcp notes.txt notes.bak
Open the filenano notes.txt
Search (exact match)Ctrl+W
Save and quitCtrl+X, then Y
Quit without savingCtrl+X, then N

Missions

  • Install Nano
  • Create notes.txt with touch
  • Back it up with cp
  • Open it with Nano
  • Change the content
  • Search for the word Pi
  • Quit without saving
  • Reopen, edit, save and quit

Stuck? Type ls to list files, help for hints.

Practice terminal

How to teach this: Fading prompts

TechniqueDemo the full task. Next round, give only the checklist. Last round, give only the goal.
Why it worksTyping commands from memory builds recall. Support is removed step by step.
In classRound 1: commands visible. Round 2: just the missions. Round 3: “Back up and edit a file”.
Watch outTypos are common. Teach reading the error message instead of retyping blindly.
